# Защитные механизмы

> Полная карта механизмов контроля: трёхслойная модель, временная шкала срабатывания,
> edit-time хуки, каталог детерминированных гейтов, кодогенерация с проверкой дрейфа,
> самопроверяемые гейты, фитнес-функции, CI и человеческие шлюзы.

Базовая идея ([01 — Проблемы и преимущества](01-problems-and-advantages.md)): ИИ —
вероятностный исполнитель.
Защита состоит не в том, чтобы добиться от модели безошибочности, а в том, чтобы
**окружить её детерминированными проверяющими** так, что любая отдельная ошибка обязана
пережить _несколько независимых машинных проверок_, прежде чем достигнет `main`.

```
        НЕДЕТЕРМИНИРОВАННОЕ                ДЕТЕРМИНИРОВАННОЕ
        ┌─────────────┐    пишет          ┌───────────────────────────┐
        │  ИИ-агент   │ ───────────────►  │  хуки · гейты · кодоген    │
        │   (LLM)     │                   │  drift-проверки · CI       │
        └─────────────┘  ◄─────────────── └───────────────────────────┘
                          обратная связь   каждое правило читает реальные
                                           файлы, проверяет инвариант,
                                           сообщает об ошибке
```

## 1. Трёхслойная модель — основа всей конструкции

Каждое правило относится ровно к **одному** слою, выбранному по _типу_ требуемой гарантии
(источник модели — [`docs/design-system-ai-tooling-plan.md`](../design-system-ai-tooling-plan.md), §1):

| Слой                  | Гарантия                                             | Режим отказа                 | Где реализован                                                            | ADR        |
| --------------------- | ---------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------- | ---------- |
| **Детерминированный** | _Точность_ — успешный гейт подтверждает свойство     | Блокирует merge (CI red)     | `check:*`, ESLint, `tsc`, покрытие, `adr.py lint`, gitleaks, CodeQL       | 0078       |
| **Структурный**       | _Полнота_ — снижает частоту нарушений в цикле агента | Предупреждает / подсказывает | `ds:*`, [`.claude/skills/*`](../../.claude/skills), PostToolUse-подсказки | 0077       |
| **Судейский**         | Неустранимое человеческое решение                    | Требует человека             | Перечень human-only действий (см. §9)                                     | 0046, 0047 |

> Идея слоёв формализована тремя «мета-ADR»: хуки как edit-time слой (0076), навыки и
> ревью-субагенты как структурный слой (0077), самопроверяемые гейты и escape-hatch для
> технического долга (0078).

## 2. Временная шкала — где срабатывает каждый механизм

Одно изменение проходит до **четырёх** машинных контрольных точек, прежде чем его увидит
человек. **Ни одна не доверяет предыдущей.**

```
① Пока агент РЕШАЕТ           структурный слой · warn
   ds:signature (дубликаты) · ds:states (набор состояний) · навыки
        │
        ▼
② На КАЖДУЮ правку файла      хуки · block/nudge
   PreToolUse:  guard-protected-files  — блокирует запрещённые записи
   PostToolUse: post-edit-checks       — prettier · scoped eslint · drift-подсказки
        │
        ▼
③ Перед PR (локально)         детерминированный слой · block
   навык pre-pr-gate: typecheck · lint · check:* · build · coverage
        │
        ▼
④ CI на PR                    детерминированный слой · required
   quality job (упорядоченные шаги) · secret-scan (gitleaks) · CodeQL
        │
        ▼
⑤ Merge                       судейский слой · human-only
   ≥1 одобрение человека ≠ автор; совещательный ИИ только информирует
```

Ключевой инвариант: **«зелено локально — зелено в CI»** — один и тот же набор `check:*`
выполняется и в `pre-pr-gate`, и в `ci.yml`.

## 3. Edit-time хуки — ближайший к моменту правки рубеж

Хуки превращают _прозу_ `CLAUDE.md` в _механическое_ принуждение в тот момент, когда агент
касается файла. Конфигурация — [`.claude/settings.json`](../../.claude/settings.json).

### 3.1 PreToolUse — [`scripts/hooks/guard-protected-files.mjs`](../../scripts/hooks/guard-protected-files.mjs)

Срабатывает на `Write | Edit | NotebookEdit | Bash`. Завершается с кодом `2` (блокировка с
указанием причины) или `0` (разрешение). При неожиданных ошибках хук **fail-open** —
сбойный хук не должен блокировать любую правку.

| Что блокирует                                           | Почему                                        | ADR        |
| ------------------------------------------------------- | --------------------------------------------- | ---------- |
| `vitest -u` / `--update` (регенерация снапшотов)        | Бейзлайны обновляются только осознанным ревью | 0040       |
| Запись в `.env`, `.env.local`, … (кроме `.env.example`) | Секреты предоставляет человек, в git их нет   | 0018, 0046 |
| Правки `docs/decisions/constraints.md`                  | Реестр клиентских мандатов — только человек   | 0046       |
| Запись в `tailwind.config.*`                            | Только CSS-first `@theme`, без конфиг-файла   | 0032       |
| Правка _принятого_ ADR на месте                         | Записи неизменяемы; требуется замещение       | 0001       |

### 3.2 PostToolUse — [`scripts/hooks/post-edit-checks.mjs`](../../scripts/hooks/post-edit-checks.mjs)

Срабатывает на `Write | Edit`. Выдаёт детерминированную обратную связь _внутри цикла
агента_, ещё до CI:

- Всегда: `prettier --write` по файлу — тем же проходом форматируется и эта документация.
- Правка `globals.css` → **подсказка** выполнить `gen:tokens` (`@theme` — источник токенов).
- Правка `migrations/*.sql` → **подсказка** выполнить `gen:types`.
- Правка `src/components/**` → `eslint` по файлу (токен-гейт); нарушение → **блокировка** (exit 2).
- Правка `*.design-intent.ts` / `*.stories.tsx` → `check:design-intent` по компоненту
  (подсказка: промежуточная ошибка в процессе создания компонента ожидаема).

Граница между блокировкой и подсказкой проведена осознанно: нарушения токенов
перехватываются в момент написания, тогда как напоминания о дрейфе остаются
необязательными, поскольку временное расхождение в процессе работы естественно.

## 4. Каталог детерминированных гейтов `check:*`

Это блокирующие в CI механические проверки. Каждая читает реальные файлы, проверяет
инвариант и завершается с ошибкой при его нарушении. На момент написания их **18** (плюс
`typecheck`, `lint`, `format:check`, `test:coverage`). Все определены в
[`package.json`](../../package.json).

### 4.1 Дизайн-система (бандл `npm run check:design-system`)

| Гейт                  | Что отвергает                                                                                                                     | ADR       |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `check:tokens`        | сырой hex/oklch, инлайн-`style` с сырыми значениями, сырые `fill`/`stroke` в SVG, числовая палитра Tailwind в `src/components/**` | 0058      |
| `check:boundaries`    | dependency-cruiser: импорт primitive→composite, импорт не через `index.ts`, циклы, модули-сироты                                  | 0060      |
| `check:graph`         | расхождение композиционного графа (`composedOf`/`usedIn`) с реальным графом импортов                                              | 0059/0060 |
| `check:design-intent` | рассинхрон `design-intent.ts` с реальностью: api↔props, покрытие состояний, states↔stories, meta↔graph                            | 0062      |
| `check:seals`         | форму/наличие Figma drift-seal (инертен, пока нет Figma-проекта)                                                                  | 0063      |
| `check:i18n`          | недостающие ключи локалей, нарушенный ICU-синтаксис                                                                               | 0055      |
| `check:stories`       | модуль в `src/components/**` без колокейт-историй                                                                                 | 0042      |
| `check:fsd`           | нарушения границ Feature-Sliced Design (Steiger)                                                                                  | 0066      |

### 4.2 Целостность ADR и Claude-инфраструктуры

| Гейт              | Что отвергает                                                                                                                                                              | ADR  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| `check:claude`    | неразрешимые ссылки в навыках/агентах/командах: ADR-номер, npm-скрипт, путь `scripts/*` или перекрёстную ссылку, которая не резолвится                                     | 0067 |
| `check:claude-md` | рассинхрон `CLAUDE.md` ↔ цитирования принятых ADR (в обе стороны)                                                                                                          | 0067 |
| `check:citations` | неразрешимые цитаты `ADR-NNNN` / `CON-00x` на операционных поверхностях                                                                                                    | 0067 |
| `check:debt`      | escape-hatch без обязательного обоснования: `eslint-disable`, `"use no memo"`, a11y-opt-out, `applicable:false`, карантинный/`skip` тест; просроченные таймбоксы карантина | 0078 |

(Целостность самого корпуса ADR — нумерация, перекрёстные ссылки, обязательные секции,
свежесть индекса — проверяет `adr.py lint`, он же навык `adr-audit`.)

### 4.3 Безопасность и цепочка поставок

| Гейт                | Что отвергает                                                    | ADR  |
| ------------------- | ---------------------------------------------------------------- | ---- |
| `check:audit`       | зависимости с уязвимостями уровня high+ (`npm audit --omit=dev`) | 0069 |
| `check:action-pins` | `uses:` в воркфлоу, не закреплённый по полному commit-SHA        | 0070 |
| `check:licenses`    | зависимость с лицензией вне SPDX-allowlist                       | 0071 |
| `check:spelling`    | орфографические ошибки в `**/*.md` (cspell)                      | 0074 |
| `check:commits`     | сообщения коммитов не по Conventional Commits (commitlint)       | 0072 |

### 4.4 Мета-гейт

| Гейт          | Что отвергает                                                                      | ADR  |
| ------------- | ---------------------------------------------------------------------------------- | ---- |
| `check:gates` | **гейт, который не смог отвергнуть собственного подсаженного нарушителя** (см. §6) | 0078 |

## 5. Единый источник истины — против «отмывания знаний»

Наиболее тонкий класс отказов возникает, когда агент следует правилу, которое _выглядит_
авторитетным, но незаметно разошлось с CI. Защита: всё, чему агент обязан подчиняться,
**генерируется** из единственного канонического источника и **проверяется на дрейф в CI**.

```
src/app/globals.css  @theme  — ИСТОЧНИК токенов
        │  gen:tokens
        ├──► tokens.generated.ts     (типизированный union)
        ├──► tokens.allowlist.json   (allowlist для линтера)  ──► ESLint-гейт ─┐
        └──► tokens.agent-rules.md   (то, что читает АГЕНТ)   ──► знание агента┘
                                                                    тот же список
        │  CI: gen:tokens && git diff --exit-code
        └──► ❌ CI завершается ошибкой, если регенерация изменила артефакты

Живая схема Supabase ── gen:types ──► database.types.ts ── проверка дрейфа ──► ❌
```

Поскольку allowlist линтера и справочник для агента формируются за **один проход**
`gen:tokens` по **одному** блоку `@theme`, знание агента и требования CI **не могут
незаметно разойтись**. Сгенерированные артефакты не редактируются вручную.

## 6. Гейты, которые проверяют себя (P6)

Гейт, который не способен завершиться ошибкой, неотличим от его отсутствия. `check:gates`
для каждого пользовательского правила выполняет следующее:

```
для каждого пользовательского гейта:
    подсадить заведомо плохой ввод ─► запустить гейт ─► убедиться: НЕнулевой выход
                                                          │
                              если гейт пропустил нарушителя ─► ❌ ошибка CI
    (состояние восстанавливается в finally)
```

Проверка выполняется в CI наравне с остальными: контролирующие механизмы сами находятся
под контролем.

## 7. Фитнес-функции — защита _сохранённого замысла_

Помимо синтаксиса, репозиторий кодирует **замысел как данные** и сверяет его с
реальностью. Замысел, которому противоречит код, приводит к ошибке CI и требует изменить
либо замысел, либо код.

- **Композиционный граф** (`composedOf`/`usedIn`, точечное множество `compositionSignature`)
  — _нисходящий_ замысел, выстроенный по общности интерфейсов _до кода_. `check:graph`
  сверяет его с _восходящим_ графом импортов dependency-cruiser (ADR 0059/0060).
- **Контролируемые словари** под [`src/design-system/`](../../src/design-system)
  (`usage-roles.ts`, `archetypes.ts`, реестр архетип→состояния, матрица приоритета
  состояний) — **закрытые списки, составленные человеком**. Ссылка на неизвестную
  роль/архетип приводит к ошибке `tsc` (ADR 0061).
- **`design-intent.ts`** для каждого компонента выводит API из множества `usedIn`, а не
  назначает его произвольно, и покрывает состояния **вычитанием** из обязательного набора
  архетипа — пометка `applicable: false` _требует записанного обоснования_.
  `check:design-intent` проверяет api↔props, покрытие состояний и контракт states↔stories
  (ADR 0062).

> **Идея «покрытие вычитанием».** Состояния не перечисляются по факту обработки — при
> таком подходе их легко недосчитать. Отсчёт идёт от полного обязательного набора
> архетипа, и каждое пропущенное состояние требует обоснования. Молчание — провал, а не
> зачёт.

## 8. CI — детерминированный последний рубеж

[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) (Node 24, `npm ci`) на каждый
PR запускает параллельные обязательные джобы; все по умолчанию least-privilege (read-only).

**Quality gate (упорядоченные шаги):**

```
typecheck → lint → format:check → check:stories
  → check:boundaries → check:graph → check:design-intent → check:seals
  → check:i18n → check:gates → token-drift (gen:tokens + git diff --exit-code)
  → build → test:coverage (≥80%)
```

Рядом выполняются **secret-scan** (gitleaks, ADR 0056 L1) и **Claude-infra integrity**
(`check:claude` / `check:claude-md` / `check:debt`). Отдельными воркфлоу идут **CodeQL**
([`codeql.yml`](../../.github/workflows/codeql.yml)), **Chromatic**
([`chromatic.yml`](../../.github/workflows/chromatic.yml)) и **проверка ссылок в docs**
([`links.yml`](../../.github/workflows/links.yml)).

- **Все шаги quality-джобы блокируют merge**: любой красный результат отклоняет PR.
- **Покрытие ≥ 80 %** (ADR 0008); только `hotfix/*` или PR с меткой `hotfix` обходят
  _порог_ — тесты при этом всё равно выполняются, и больше ничего из гейта не обходится.
- **Без глобальных повторных запусков** (ADR 0049). Обязательные статус-проверки —
  только детерминированные.

> **Lean-bootstrap.** Пока в шаблоне нет продуктового кода, два более тяжёлых набора —
> Playwright e2e (с воспроизведением миграций) и Storybook test-runner smoke — временно
> выполняются **локально**, а не в CI; отклонение отслеживается в
> [`docs/bootstrap-plan.md`](../bootstrap-plan.md) и возвращается в CI до первого
> промоута `dev → main`.

## 9. Человеческие шлюзы — судейский слой

Агент пишет большую часть кода, но каждое **необратимое** или **судейское** действие
закреплено за человеком:

- принятие ADR;
- настройки репозитория и branch-protection;
- промоут и откат production;
- выдача, ротация и раскрытие секретов;
- правка `constraints.md`;
- merge в `dev` и `main`;
- утверждение визуального бейзлайна в Chromatic UI;
- разрешение коллизий usage-role и отклонений набора состояний.

Совещательные ИИ-задания (`ai-advisory.yml`, `ai-ci-triage.yml`) оставляют комментарии со
ссылками на ADR-номера и **никогда не являются обязательными проверками**; все они инертны,
пока человек не предоставит `AI_API_KEY` (провайдер-агностично, через OpenAI-совместимый
клиент, ADR 0075).

### Защита от галлюцинаций и drift-seal (ADR 0063)

При утверждении API агенту показывают **изображение из Figma, которое он не
контролирует**, — никогда его собственный рендер и никогда code-path Figma. Артефакт
запечатывается (`renderHash` + `figmaFileVersion`) и служит детектором дрейфа. Агент
**никогда не утверждает собственный визуальный бейзлайн** (Chromatic UI — только человек).

## 10. Циклы обратной связи — как ошибка становится исправлением

Защитные механизмы — половина системы; вторая половина определяет, как _обнаруженная
ошибка превращается в правило_ и как набор правил _пополняется от наблюдаемых дефектов_:

1. **Цикл правки (секунды).** PostToolUse-хуки показывают результат lint и проверки дрейфа
   в момент записи файла, и агент исправляет ошибку немедленно.
2. **Реактивный рост (за волну).** [Defect Log](../design-system/defect-log.md) фиксирует
   каждое _недостающее или неоднозначное_ правило; инвариант проходит путь от прозы к
   проверяемой ревью Confirmation и далее к исполняемому Stage-1-гейту при первом нарушении
   (ADR 0064).
3. **Аудит дрейфа (плановый).** ИИ обходит раздел Confirmation каждого принятого ADR и
   докладывает `confirmed / drifted / unverifiable`; решение принимает человек — исправить
   код или открыть замещающий ADR, но не менять принятое решение незаметно (ADR 0054).

## На чём основаны правила

Каждый защитный механизм восходит к одному из четырёх обоснованных источников — ни один не
создан агентом произвольно:

| Источник                                          | Что фиксирует                              | Полномочия                                          |
| ------------------------------------------------- | ------------------------------------------ | --------------------------------------------------- |
| **ADR** (`docs/decisions/`, MADR)                 | каждое обдуманное архитектурное решение    | принимается человеком; после принятия неизменяемо   |
| **Constraints** (`constraints.md`, CON-00x)       | внешне заданные клиентские мандаты         | файл только для человека; цитируется из ADR         |
| **Контролируемые словари** (`src/design-system/`) | закрытые списки: роли, архетипы, состояния | составляет человек; неизвестная ссылка ломает `tsc` |
| **Design-токены** (`globals.css @theme`)          | _значения_ токенов — каноничны в коде      | Figma read-only, конформна коду                     |

Цепочка всегда одна: **решение человека → записанный артефакт → сгенерированное правило →
механический гейт → агент подчиняется**. Агент никогда не создаёт правило, по которому его
оценивают.
